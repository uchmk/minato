# minato の設計（2026-10-12 に確定）

持ち主が HTML のモック（[mock/minato.html](mock/minato.html)）で確かめて決めたこと。迷ったらモックを開いて同じ動きにする。
モックは見本のデータ（`items`・`RUNS`・`NOTES`）で動き、GitHub には触らない。トーストの小さい字が、実物で呼ぶ API の見当。

## 全体

- 窓は 1 枚。上から、タイトルバー・ビュー・キーの帯（keybar）。
- タイトルバー: 左にロゴと `minato`（漢字の「港」は付けない）とビューのタブ、真ん中にパレットの欄（`Ctrl+Shift+P`）と通知の鈴（未読の数）、
  右にアカウントと窓のボタン。
- ビューと数字のキー: `1` 受信箱、`2` 一覧、`3` Actions、`4` ボード、`5` 状況（v0.40.0 から）、`,` 設定。
- `y`（v0.40.0 から）: 選んでいるもの（項目・実行・カード・状況の行）のページのリンクをクリップボードに写し、トーストで知らせる。
- keybar: 左に今の場面で使えるキー（いちばん勧めるものは強調）と `F5`・`@`・`F1` を幅に入るだけ（v0.39.21 から。前はビューのキー 5 つまで）、
  右に「⟳ 12s 前」（最後の同期。`F5` の同期の間は「⟳ 取得中 3 / 12」を強調の色で）・「API 4,812/5,000」（レート制限の残り）・
  時計（`2026/10/12 (Mon) 17:40`、ito の共通仕様の書き方）。入りきらないときは後ろのキーから消え、次に `F1` の言葉が消える。
- `F1`（`?`）で全部のキーの一覧、`gg` で先頭・`G` で末尾（詳しくは上と終わり）、`u` で最後の操作を取り消す、`n` で通知、
  `F5` で今すぐ同期、`@` で持ち主の切り替え（下のパレット）。
- `o` は内蔵ブラウザ（ito-browser、v0.26.0 から）でビューの右に開く。タイトルバーの下・keybar の上の右側に、アドレスの欄（← ⟳ ↗ ✕）と
  ページ。左の線をドラッグして幅を変える。`Esc`（ほかに閉じるものが無いとき）か ✕ で閉じる。`O` はシステムのブラウザで開く。
  Linux には内蔵ブラウザが無いので `o` もシステムのブラウザ。サインインは状態のフォルダの `webview` に残る。
- 対象のリポジトリは設定で選ぶ（見本は uchmk の kura・tsumugi・yagura・ito）。リポジトリごとの色の札（tag）が全部の画面に出る。

## 折りたたみ（スクロールバーを出さない）

- どこにもスクロールバーを出さない。
- 並び（受信箱のカード・一覧の行・Actions の実行・ボードのカード・通知）が箱に入りきらないときは、選んでいる行から近い順に
  （同じ近さなら上を先に）入るだけの行をそのままの高さで出し、残りを隠して、上下に「⋯ 上に N 件」「⋯ 下に N 件」の行を出す。
  1 行に畳むことはしない（v0.25.0 から。前はモックの `fold()` どおり遠いものから 1 行に畳んでいた）。
- 選びを動かすたび、窓の大きさが変わるたびに計算し直す。
- 長い文（本文・ログ）はホイールで動くが、バーは出さない。
- この計算は egui に依らない関数にし（行の高さ・箱の高さ・選んでいる番号 → 行ごとの「出す・隠す」と上下の件数）、単体テストを付ける。

## 1 受信箱

「あなたの番のもの」だけ。通知（全部の出来事）とは別物。

- 左の列（tsumugi のサイドバーの形）:
  - 頭に `受信箱 N of M`、その下にラベルの札の並び（タグで絞る）。
  - 3 つの組: **あなたの番**（mine）・**待っている**（wait）・**今日済んだ**（done）。
  - カード 1 枚: 種類の札、題と経過（3h）、`uchmk/repo #N · 補足` を等幅で、色付きの「なぜここにあるか」（why）の 1 行、リポジトリの札とラベル。
    カードの左の縁は色（tone）。
  - 下（左下）に 2 段の札: **状態**（すべて・あなたの番・待っている・済んだ）と**リポジトリ**。組み合わせて絞れる。タグの絞り込みとも組み合わさる。
- 右は選んだものの詳しく（一覧と同じ詳しくの欄）。いちばん上に「次にやること」（`next`: キー・名前・一言）と、ほかの手（`alt`）。
- 受信箱に入れる規則（設定で付け外し、既定はモックのとおり）:
  1. 赤い CI（自分の PR・main）
  2. マージできる PR
  3. 自分への質問・メンション
  4. needs-owner の質問
  5. 誰にも振っていない finding
  6. レーンが止まった（lane-stalled）
  7. dependabot の PR（既定は切）
  8. 安全のアラート（critical・high の未対応のもの。v0.50.0 から。カードの題はアラートの内容、キー `Enter` `o` でブラウザの該当ページ）
- キー:
  - `j` `k` 次・前、`Space` 詳しくをめくる、`r` 書く、`d` 済み、`s` あとで（明日 9:00 に戻る）、`o` ブラウザで開く（`O` システムのブラウザ）、`u` 取り消す
  - `m` マージ（PR、merge コミット。`PUT /repos/{o}/{r}/pulls/{n}/merge`、`merge_method=merge`）
  - `a` 自分に振る（`POST …/issues/{n}/assignees`）、`R` 失敗だけ再実行、`e` ログ、`g` その実行を Actions で開く
  - `f` `F` `t` 状態・リポジトリ・タグの絞り込みを順に回す
- 「済み」「あとで」は GitHub を変えないローカルの印。手を打つと次のカードへ進み、トーストで結果と `u` を出す。

## 2 一覧

- 3 列: 絞り込み（c1）・項目の並び・詳しく（書く欄つき）。`h` `l` で列を動く。
- 絞り込み: リポジトリ・種類（Issue / PR / Discussion）・author・保存した絞り込み（自分に振られたもの・CI が赤い PR など）。
- 行は 3 行: 1 行目 題、2 行目 ラベル、3 行目 `uchmk/kura #361 · uchmk opened 3h ago`。
- 詳しく: 題・状態・項目の値・CI のチェック（ログを開ける）・変更したファイル（PR、v0.40.0 から）・やりとり（timeline）。
- 変更したファイル: PR の詳しくの「変更したファイル（N）」に、パスと `+足した行`（緑）・`−消した行`（赤）を 15 件まで、残りは「ほか N 件」。
  詳しくの GraphQL の問い合わせで `files(first: 100)` も聞く。
- `i` で受信箱に入れる（ローカルの印）。

## 書く欄（composer）

- 詳しくの下。`r` で入る。Markdown。`Ctrl+Enter` Comment、`Ctrl+Shift+Enter` 書いて閉じる、`Ctrl+P` Preview と Write の行き来、
  `Ctrl+B` `Ctrl+I` 太字・斜体、`Ctrl+K` リンク、`Esc` やめる。
- 上に項目の札が並び、`Alt+文字` で選ぶ窓（picker）が開く（文字で絞る、`Enter` で付け外し・決める）:

  | 項目 | キー | 値のもと | 既定 |
  | --- | --- | --- | --- |
  | Labels | `Alt+L` | リポジトリのラベル | 出す |
  | Assignees | `Alt+A` | 担当（リポジトリに入れる人） | 出す |
  | Status | `Alt+S` | Project「uchmk」の Status（ボードの列） | 出す |
  | Milestone | `Alt+M` | リポジトリ | 出さない |
  | Priority | `Alt+P` | Project の独自の項目 | 出さない |
  | Reviewers | `Alt+R` | リポジトリ（PR だけ） | 出さない |

- Project の項目（Status・Priority など独自のもの）は GitHub から読み、GraphQL の `updateProjectV2ItemFieldValue` で書く。
  ほかは REST。Discussion には項目を出さない。

## 3 Actions

- 3 列: 絞り込み（リポジトリ・状態・workflow）・実行の並び・詳しく。
- 実行の行: 状態の印、題、workflow の札、event、branch、`uchmk/repo · #番号 · 起こした人 · 経過`、かかった時間、受信箱に入っていれば「受信箱」の印。
- 詳しく: 次にやること、job ごとの結果とログ、同じ workflow の直近 10 回、成果物（artifacts）、リリースのファイル。
- リリースのファイル（v0.39.20 から）: workflow のファイルの名前に `release` を含む実行は、リポジトリの新しい 10 件のリリース
  （`GET /repos/{o}/{r}/releases?per_page=10`）から、実行のコミット（`target_commitish` が `head_sha`）で、実行の間に公開された
  （`published_at` が始まりから終わりの 1 分後まで）ものを探し、そのファイル（assets）を「リリースのファイル · タグ」に名前と大きさで出す。
  終わった実行の分は、見つけたリリースだけを状態のフォルダに残す。
- 見た実行（v0.39.19 から）: 成功した実行を Actions で 1 秒選んでいると「見た」になり、選びが離れると並びから消える
  （選んでいる間は残る）。v0.40.2 から取り消し（cancelled・skipped など）も同じ。失敗・実行中・待ちは消えない。状態の絞り込みの「見た」で見られ、ほかの絞り込みと数には入らない。
  見た実行の id は状態のフォルダの `seen-runs.txt` に新しい 1000 件まで残る。同じ実行を走らせ直すと（成功でも取り消しでもなくなるので）また出る。
- キー: `R` 失敗だけ再実行（`POST …/actions/runs/{id}/rerun-failed-jobs`）、`X` 止める（走っている・待っているとき）、
  `D` 手で走らせる（workflow_dispatch、入力を聞く）、`e` ログ、`p` 元の PR、`o` ブラウザ。
- 見張り（`w`、v0.40.0 から）: 走っている・待っている実行で `w` を押すと見張り、もう一度でやめる（終わった実行は「もう終わっています」）。
  見張っている実行の行の 3 行目の右に「◉ 見張り中」。見張っている間は Actions を開いていなくても実行の並びを開いているときと同じ間隔で問い、
  終わったらシステムのトースト（ito-notify、成功は「実行が終わりました」・失敗は「実行が失敗しました」・取り消しは「実行が取り消されました」、
  リポジトリ・workflow・題）と音で知らせる（Windows の集中モードの間は音を出さない）。どちらを出すか・どの音かは設定の「通知」のページで
  終わり方ごとに選ぶ（v0.41.0 から）。Webhook のアドレスがあればそこにも送る（v0.42.0 から）。minato の窓の中の知らせはいつも出る。
  見張りは起動し直すと消える。

## 4 ボード

- 列は Project「uchmk」の Status（Todo / In progress / Review / Done）。カードは題・種類・リポジトリ・ラベル。
- `h` `l` 列、`j` `k` カード、`H` `L` でカードを隣の列へ（GitHub の Project にも書く）、マウスのドラッグでも動く、`Enter` で一覧で開く。

## 5 状況（v0.40.0 から）

- 上から 3 つの節。持ち主（並べている持ち主も）を見出しの右に出す。入りきらないときは折りたたむ（スクロールバーは出さない）。
  - レーン: 項目のうちラベル `lane-status` の issue（「Lane status: win」など）を 1 行ずつ。本文の「Last firing」「This firing:」
    「Failed runs in a row:」を読む。印は緑（良い）・黄（3 時間より古い）・赤（`lane-stalled` か、続けて失敗）。右に経過、
    「N 回続けて失敗」、「止まっている」の札。まだ起動していなければ「まだ起動していない」。
  - リリース: 実行の並びと同じリポジトリの最新のリリース（下書きは除く、`GET /repos/{o}/{r}/releases?per_page=5`）。タグ・ファイルの数・
    ファイルがあるのにノートに SHA-256 の表が無ければ「⚠ SHA-256 の表なし」・経過と、そのタグからの main のコミットの数
    （`GET /repos/{o}/{r}/compare/{tag}...HEAD` の `ahead_by`、1 以上は強調の色）。状況を開いている間だけ 5 分ごとに問う。
  - あなた待ち: 開いている項目のうち `needs-pc`・`question`・`lane-review` のラベルのもの（この順、各ラベルの中は新しい順。レーンの issue は除く）。
- `j` `k` 選ぶ、`Enter` 開く（あなた待ちの項目は一覧で、ほかはブラウザで）、`o` 内蔵ブラウザ、`O` システムのブラウザ、`y` リンクを写す。
  クリックで選び、ダブルクリックで開く。どれかのレーンが赤ならタブ「5 状況」に赤い点。

## 6 安全（v0.50.0 から）

- 並べているリポジトリ（実行の並びと同じ）の、開いている **コードスキャン**・**Dependabot**・**シークレットスキャン** のアラートを、深刻度の高い順
  （critical・high・medium・low、同じ深刻度では古い順）に 1 行ずつ。行: 深刻度の点と名前・種類・リポジトリの札・内容（規則やパッケージ）・場所・経過。
  見出しの右に深刻度ごとの件数。機能が切れている・読む権限が無いリポジトリは黙って飛ばし、「N 件のリポジトリは読めません」と添える。
  入りきらないときは折りたたむ（スクロールバーは出さない）。
- 取得: `GET /repos/{o}/{r}/code-scanning/alerts`・`dependabot/alerts`・`secret-scanning/alerts`（`state=open`）。
  受信箱が critical・high を出すため、安全を開いていなくても 15 分ごと、開いている間は 5 分ごとに問う。
- `/` で絞り込む（リポジトリ・ルール・パッケージ・場所・深刻度・種類に語が全部あるもの。v0.52.0 から）。
- `j` `k` 選ぶ、`Enter` `o` ブラウザで開く、`y` リンクを写す。クリックで選び、ダブルクリックで開く。
- `x` で閉じる。確認（理由つき: コードは「修正しない」、Dependabot は「許容できるリスク」、シークレットは「修正しない」）を出し、
  `Enter` で `PATCH` を送る（`state=dismissed`＋理由）。トーストで結果を出し、`u` で開き直す（`state=open`）。
- critical か high があれば、タブ「6 安全」に赤い点。同じものは受信箱の「あなたの番」に出る（受信箱の安全の規則）。

## 設定（`,`）

- ページは 一般・テーマ（共通）・ビュー（minato のもの）・キー・通知（ito の `docs/common-spec.md` の並び。v0.44.0 から。前は 一般・テーマ・通知・ビュー）。
- 「キー」のページ（v0.44.0 から、kura・yagura・tsumugi と同じ `ito_prefs::keys_page`）: 操作ごとに 1 行で、今のキーをチップで並べる。
  - 検索（説明・`run`・キー・節の名前）、「⌨ キーで探す」、節で絞る、「変えたものだけ」。
  - チップを押すか ＋ で受け取り、`Enter` で決めて keymap.toml の `prepend_keymap` に書く（`Esc` でやめる、`Backspace` で 1 つ戻す）。
    × で外す（既定のキーは `run = "none"`）、↺ でその操作を既定に戻す。書くのは変えた分だけで、何も変えなければファイルを作らない。
  - 節の名前は どこでも（`[main]`）・受信箱・一覧・Actions・ボード・状況・通知（`[notes]`）。説明は日本語の表で訳す。
  - 受け取っている間は `Esc`・`F1`・`F5`・`Ctrl+=` などもページに渡す。下の「変えられないもの」を割り当てようとすると、
    決める前に「minato が先に読むので動かない」と出す。
- 「通知」のページ（v0.41.0 から、tsumugi の通知のページと同じ形）: `w` で見張った実行が終わったときの知らせ方。
  - 上に「試しに送る」（システムの通知と成功の音、Webhook のアドレスがあればそこにも）と「既定に戻す」（Webhook のアドレスと形式は残す）。
  - 「知らせるとき」の表: 列は 成功・失敗・取り消し（skipped なども）、行は「システムの通知」「音」のスイッチ（Webhook は下のカードに、1 つごとの「知らせる終わり方」のスイッチ）。既定は全部入り。
  - 「鳴らす音」: 終わり方ごとの音（やわらかいチャイム・低い音・警告音・システムの既定、`ito_notify::SOUNDS`、▶ で鳴らす。
    既定は成功と取り消しがチャイム、失敗が警告音）と「Windows の集中モードに従う」（既定は入り。切ると集中モードでも鳴る）。
  - 「Webhook」（v0.42.0 から、tsumugi の `[notify] webhook` と同じ。v0.53.0 から何個でも。「追加」「削除」「テストを送る」は 1 つごと、上のテストは全部）: アドレス（ntfy のトピック・Slack や Discord の webhook・JSON を受ける
    任意のアドレス。Enter か欄を離れたときに書く。空なら送らない。http(s) で始まらなければ赤い注意を出して送らない）と形式
    （ntfy・Slack・Discord・JSON、`ito_notify::FORMATS`。Discord は v0.47.0 から）。送るのは `ito_notify::webhook::send`
    （`curl -f`、別のスレッド。届かなかったときと、相手が HTTP のエラーで断ったときは 30 秒後にもう 1 回）。
    状態は失敗が `error`（ntfy は ❌・優先度 high）、成功と取り消しが `done`。JSON の `folder` はリポジトリ。
  - `minato-settings.json` の `notify`（`system`・`sound`・`sounds`・`focus`・`webhooks`＝`url`・`format`・`on` の並び。前の `webhook`・`webhook_url`・`webhook_format` は最初の 1 つとして読む）に残る。
    知らない音・形式の名前は既定に戻す。
- ito の共通の設定の画面（`ito-prefs`）に、minato の「ビュー」のページ（英語は Views）を足す（v0.39.13 まで名前は「minato」だった）:
  - 書く欄に出す項目（`Space` 出す・出さない、`J` `K` 並びを変える）。Project の独自の項目は GitHub から読んで足される。
  - 受信箱に入れるもの（上の規則の付け外し）。
  - 対象のリポジトリ、同期の間隔。
  - 持ち主（空なら自分）。前に使った持ち主は新しい順に 8 人まで残り（`owners`）、`@` のパレットに並ぶ。
    `uchmk, rust-lang` のようにカンマか空白で区切ると、2 人目からを並べて見る（`also`、v0.40.0 から）。

## キーの割り当て（keymap.toml、v0.43.0 から）

- kura・yagura・tsumugi と同じ ito-keymap（ito の `docs/common-spec.md`）。既定は `crates/minato/src/defaults/keymap.toml`、
  使う人のものは `<設定のフォルダ>/uchmk/minato/keymap.toml`（Windows は `%APPDATA%\uchmk\minato\keymap.toml`）で、節ごとに重ねる
  （`keymap` で置き換え、`prepend_keymap`・`append_keymap` で前と後ろに足す）。2 秒ごとに見て、変わったら読み直す。
- 節は `[main]`（どのビューでも）と、ビューごとの `[inbox]`・`[list]`・`[actions]`・`[board]`・`[status]`、通知の欄の `[notes]`。
  ビューの節が `[main]` より先に引かれる。`run = "none"` でキーを止める。`g g` のような続けて押すキーも書ける。
- keybar・`F1` の一覧・「次にやること」の札・ほかの手の札・パレットは、今効いているキーを出す（割り当てが無ければ出さない）。
- 変えられないもの: `Esc`、`F1`、`F5`、`Ctrl+,`、`Ctrl+Shift+P`、`Ctrl+=` `Ctrl+-` `Ctrl+0`、書く欄・パレット・Actions の
  フォームの中のキー、確かめる問い（`Enter` と `Esc`）。これらを keymap.toml に書くと、その行は飛ばして知らせる。
- `Ctrl+C`・`Ctrl+X`・`Ctrl+V` も割り当てられる（egui がクリップボードの出来事として渡すものを、そのキーとして読む）。
- 続けて押すキーの途中（`g` を 1 回押したところ）の `Esc` は、それを取り消すだけで、ほかのものは閉じない。
- ビューの節のキーが `[main]` の続けて押すキーの頭と同じとき（`[inbox]` の `g` と `[main]` の `g g`）は、そのビューで
  `g g` が押せなくなるので知らせる。
- 読めない行は飛ばしてトーストで知らせ（最初の 1 つと残りの数）、ほかの行は効く。ファイルが読めないときは前のキーのまま。
- キーを変えても、文の中のキー（`F1` の一覧の「閉じる F1, ? か Esc」、検索の欄の `/`、「u で取り消し」など）は既定のまま。
  `F1` の一覧のキーの欄は幅が決まっていて、長いキーは終わりが切れる（受信箱の札の表はいちばん長いキーに合わせて広がる）。
- v0.43.0 で変わったこと: `Shift` と矢印はボードのカードを動かすときだけ（前はどこでも `H` `J` `K` `L`）。Actions の `Shift+→`
  （前は `L`、失敗したジョブのログ）は無くなった。`Ctrl+Enter`・`Shift+Enter` は `Enter` の代わりにならない（確かめる問いは別）。

## 通知（`n`）

- 鈴から開く右の欄。全部の出来事を新しい順に（GitHub の `/notifications`）。未読に印、受信箱に入ったものに「受信箱」の印。
- `j` `k` 選ぶ、`Enter` 開く（受信箱にあれば受信箱で、無ければ一覧で）、`A` 全部を既読（v0.42.1 まで `Shift+A` と書いていた）、`Esc` 閉じる。

## パレット（`Ctrl+Shift+P`）

- 命令と項目をまとめて探す（`#361` で番号、文字であいまい検索、ito-match）。命令にはキーを添える。
- 命令の例: 各ビューを開く、通知、保存した絞り込み（自分に振られたもの・CI が赤い PR・dependabot の PR・失敗した実行・あなたの番だけ）、
  新しい issue を書く（`c`）、今すぐ同期する（`F5`）、書く欄に出す項目を選ぶ。
- 持ち主の切り替え（v0.39.21 から）: `@` でパレットが `@` を入れた形で開く。`@login` と打つとその持ち主の行が出て、`Enter` で
  その持ち主のリポジトリ・検索・Project に切り替わる（設定の「持ち主」と同じ）。自分に戻る行と、前に見た持ち主（新しい順に 8 人まで、
  設定に残る）も並ぶ。
- 持ち主を並べる（v0.40.0 から）: パレットで `+@login` と打って `Enter` で、その持ち主のリポジトリ・項目・実行を今の持ち主のものに足す
  （持ち主が空なら自分の名前が持ち主になる）。並べている持ち主ごとに `-@login` の行が出て、`Enter` で外す。検索は
  持ち主ごとに分ける（1 つの検索は GitHub が 1000 件までしか返さないので、大きな持ち主を並べると 1 人目の項目が押し出される）。
  1 人目は今までどおり全部のページ、並べた持ち主は新しい順に 100 件ずつ（issue・PR と Discussion）。一覧の上の検索の欄は
  `user:a user:b …` と書き、保存した検索はその形で 1 つにまとめて検索する。実行の並びは持ち主ごとに新しいリポジトリ 8 つずつ。ボードは 1 人目の持ち主の Project のまま。
  アカウントの印の上の言葉と設定の「持ち主」の欄に全員が出る。

## 同期

- ワーカースレッドで間隔を置いて問い合わせる。`If-None-Match` で 304 を受けたものは数えない。レート制限の残りを keybar に出し、少なければ間隔を広げる。
- `F5`（v0.39.21 から）: 今出ているもの（検索・受信箱・通知・ボード・リポジトリ・実行の並び・開いている項目と実行）をまとめて問い直す。
  覚えたもの（ETag）は捨てないので、変わっていないものは 304 でレート制限を使わない。答えの数を keybar に「取得中 N / M」で出し、
  全部そろうか 90 秒でトースト「同期しました」を出して終わる。全部を消して取り直すことはしない（終わった実行の詳しくは変わらない）。
- 書く操作（コメント・マージ・項目・再実行）もワーカーで送り、結果をトーストに出す。失敗したら元の表示に戻す。
